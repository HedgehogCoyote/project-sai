# SAI 서비스 기획서

작성일: 2026-10-06  
문서 상태: 대화 기반 기획 초안. 아래 MVP 범위와 상세 운영 정책은 구현을 위한 제안이며, 최종 승인된 요구사항이나 현재 구현 상태를 뜻하지 않는다.

## 1. 서비스 정의

**우리에게 필요한 도구를 놓아, 우리만의 공유 공간을 만든다.**

SAI는 친구, 가족, 연인, 스터디 등 관계마다 필요한 기능을 선택해 사용하는 공유 공간 서비스다. 기능을 추가하면 기능에 대응하는 물건이나 캐릭터가 방에 배치된다. 사용자는 물건을 누르거나 기능 바로가기를 통해 일정, 할 일, 반복 할 일, 기록 등을 이용한다.

여행 전용 서비스나 캐릭터 육성 게임으로 범위를 바꾸지 않는다. 방은 관계별 기능 구성을 보여주는 인터페이스이며, 꾸미기는 기능 선택을 이해하기 쉽게 만드는 역할을 한다.

## 2. 문제와 검증할 가설

관계마다 공동으로 관리하는 일이 다르다. 스터디에는 일정과 과제가, 가족에는 반복 집안일과 공유 일정이, 친구 모임에는 약속과 투표가 필요할 수 있다. 이 예시는 사용자 조사로 검증해야 하며 시장 수요가 확인됐다는 의미는 아니다.

검증할 가설은 다음과 같다.

- 필요한 기능만 보이는 공간이 모든 기능을 제공하는 화면보다 이해하기 쉽다.
- 기능이 물건으로 표현되면 구성원이 어떤 도구를 사용할 수 있는지 쉽게 인식한다.
- 함께한 활동의 기록이 공간에 남으면 이후에도 찾아올 이유가 생긴다.

초기 검증은 가족·생활 모임과 스터디처럼 구성이 다른 두 관계에서 진행한다. 각각 필요한 도구를 선택하고, 특정 할 일을 찾고 완료하는 과정을 관찰한다.

## 3. 핵심 개념

| 개념 | 정의 |
|---|---|
| 공간 | 구성원, 권한, 활성 기능, 방 배치를 공유하는 관계 단위 |
| 기능 모듈 | 일정, 할 일, 반복 할 일, 기록 등 실제 데이터를 관리하는 도구 |
| 에셋 | 기능과 연결된 물건·캐릭터 또는 기록을 표현하는 이미지 |
| 활동 | 공간 안의 여행, 모임, 스터디 회차 등 시작과 완료가 있는 일 |
| Foot Print | 완료된 활동을 사진과 후기로 남기는 공동 기록 |
| 반복 규칙 | 주기, 시작일, 담당자를 정의하는 설정 |
| 반복 할 일 회차 | 특정 날짜에 해야 하는 실제 할 일과 완료 기록 |

관계 유형은 추천 기능을 제공하는 선택값이다. 기능을 제한하지 않으며, 어떤 공간에서든 필요한 모듈을 추가하거나 숨길 수 있다.

## 4. 기능과 방의 연결

| 방의 도구 | 실제 기능 | MVP 제안 |
|---|---|---|
| 달력 | 공유 일정 | 포함 |
| 체크리스트 보드 | 일회성 할 일 | 포함 |
| 작은 고양이 캐릭터 | 반복 할 일 | 포함 |
| 사진 앨범 | 활동 기록·Foot Print | 포함 |
| 게시판 | 투표 | 후속 확장 |
| 가계부 | 공동 지출·정산 | 후속 확장 |
| 여행 가방 | 여행 준비물 | 후속 확장 |

에셋 추가 화면에는 `독서 고양이 — 반복 할 일`처럼 물건과 기능을 함께 표시한다. 캐릭터 이름과 외형은 시안 예시이며, 기능 이름은 ‘반복 할 일’로 명확히 보여준다.

MVP에서는 공간마다 같은 모듈을 한 번만 활성화한다. 물건을 클릭하면 해당 모듈의 패널이 열리고, 방 아래에 동일한 기능 바로가기를 제공한다. 도구를 숨겨도 데이터는 보존하고 다시 추가하면 기존 데이터를 보여준다. 기록 영구 삭제는 별도 작업으로 구분한다.

## 5. 사용자 흐름과 화면

### 5.1 진입과 공간 선택

공개 소개 화면 → 로그인 또는 회원가입 → 내 공간 목록 → 선택한 공간의 방.

소개 화면은 두 추상적인 원이 접근하며 액체처럼 연결되는 표현을 유지한다. 원에 ‘나·너’ 같은 인물 라벨을 넣지 않는다.

내 공간 목록은 세로로 쌓인 행으로 구성한다. 각 행에 대표 이미지, 공간 이름, 멤버 수, 활동 수, 내 역할, `들어가기 →`를 표시한다. 행 전체로 진입할 수 있게 한다. 이미지가 없으면 기본 커버를 사용한다.

### 5.2 공간 생성과 구성

공간 이름 입력 → 관계 유형 또는 직접 구성 선택 → 추천 기능 확인·변경 → 공간 생성 → 구성원 초대.

예시 추천: 가족은 일정·반복 할 일, 스터디는 일정·할 일, 친구는 일정·기록. 추천은 초기 선택을 돕는 수단이다. 관계 정보 자체를 공개 프로필이나 민감한 분류로 이용하지 않는다.

### 5.3 방 화면

- 상단: 공간 이름, 구성원, 초대, 도구 추가, 방 꾸미기.
- 중앙: 고정 시점의 2D 방과 기능 에셋.
- 옆 패널: 선택한 기능의 내용을 표시. 선택 전에는 오늘 할 일과 다음 일정을 표시.
- 하단: 활성 기능의 이름과 바로가기.
- 모바일: 방과 패널을 위아래로 배치하고 기능을 그림 없이도 이용할 수 있게 한다.

빈 공간에서는 도구 추가를 안내한다. 권한이 없으면 꾸미기 버튼 대신 읽기 가능한 기능을 표시한다. 로딩, 저장 실패, 빈 목록 상태도 제공한다.

### 5.4 활동과 Foot Print

활동 생성 → 일정·할 일 등 준비 → 활동 완료 → Foot Print 초안 → 사진·후기 작성 → 기록 게시 → 기념품 배치.

활동 완료 시 제목과 기간을 포함한 초안만 만든다. 다른 구성원의 사진을 자동 공개하거나 게시 완료로 처리하지 않는다. 사용자가 내용을 확인해 게시한다. 한 활동에는 하나의 Foot Print가 연결되고 여러 구성원이 사진과 후기를 추가할 수 있다.

기념품을 누르면 해당 기록을 연다. 기념품을 치워도 기록은 남는다. 활동 완료와 기념품 배치는 중복 요청으로 같은 항목이 여러 번 생성되지 않게 한다. 반복 할 일의 매 회차를 자동으로 Foot Print로 만들지는 않는다.

## 6. 반복 할 일 상세 기획

### 6.1 목적

습관 형성이나 연속 달성보다 **주기적으로 다시 해야 하는 공동 업무**를 관리한다. 예: 매주 분리수거, 매월 회비 납부, 정기 공용 물품 확인.

### 6.2 등록 항목

| 항목 | 정책 제안 |
|---|---|
| 제목 | 필수 |
| 설명 | 선택 |
| 담당자 | 활성 공간 구성원 1명, 고정 담당 |
| 반복 | 매일 / 매주 선택한 요일 / 매월 선택한 날짜 |
| 시작일 | 첫 회차가 생성될 수 있는 날짜 |
| 시간대 | MVP는 Asia/Seoul로 고정 |
| 상태 | 활성 / 일시정지 |

‘2주마다’ 같은 임의 간격은 활용 예시지만 첫 버전에서는 제외한다. 푸시 알림, 순번 담당, 여러 담당자, 공휴일 보정은 후속 확장이다.

### 6.3 날짜와 완료 정책

- 회차별 상태는 미완료·완료. 예정일이 지났고 미완료이면 ‘기한 지남’으로 표시한다.
- MVP는 날짜 단위로 처리하며 예정일의 현지 날짜가 끝날 때까지 완료할 수 있다.
- 이번 회차를 완료해도 다음 회차가 완료되지 않는다. 지난 회차는 늦게 완료할 수 있다.
- 매월 선택한 날짜가 없는 달에는 마지막 날에 생성한다.
- 기한이 지난 미완료 회차가 있어도 다음 회차는 생성하며, 기한 지남 목록에서 누락을 확인한다.
- 반복 규칙 변경은 이후 생성할 회차에 적용한다. 이미 생성된 회차와 완료 기록은 자동 변경하지 않는다.
- 일시정지하면 새 회차 생성을 멈추고 기존 회차는 남긴다. 재개 시 정지 기간의 회차를 소급 생성하지 않는다.
- 담당자가 탈퇴하면 새 회차 생성을 일시정지하고 소유자에게 재지정을 안내한다. 과거 완료자는 이력으로 보존한다.

### 6.4 캐릭터 표현

캐릭터를 누르면 ‘지금 해야 할 것’, ‘기한 지남’, ‘다음 예정’을 확인한다. 각 회차에서 완료를 체크한다. 캐릭터는 기본·완료 반응 두 모습으로 시작한다. 완료 반응은 짧게 표시하고, 여러 종류의 반복 업무를 캐릭터 하나가 안내한다.

레벨, 연속 달성, 배고픔, 실패 벌점, 순위는 제외한다. 다른 구성원의 상태 표시는 공간에 공유된 담당 업무의 완료 여부만 보여준다.

## 7. 권한 정책 제안

| 작업 | 소유자 | 관리자 | 멤버 |
|---|---|---|---|
| 공간 접근·조회 | 가능 | 가능 | 가능 |
| 초대·기능 추가·숨김·방 배치 | 가능 | 가능 | 불가 |
| 일반 일정·활동·할 일 작성 | 가능 | 가능 | 가능 |
| 반복 규칙 생성·변경·일시정지 | 가능 | 가능 | 불가 |
| 반복 회차 완료 | 가능 | 가능 | 본인 담당만 |
| 사진·후기 작성 | 가능 | 가능 | 가능 |
| 타인 콘텐츠 수정·삭제 | 가능 | 가능 | 불가 |
| 역할 변경·소유권 이전·공간 삭제 | 가능 | 불가 | 불가 |

멤버는 자신이 작성한 일반 콘텐츠를 수정·삭제할 수 있다. 공동 Foot Print의 제목·대표 사진·게시 상태는 소유자와 관리자가 관리한다. 모든 권한 검증은 서버에서 수행한다. 마지막 소유자는 소유권 이전 없이 탈퇴할 수 없다. 초대 방식은 기존 사용자 초대를 우선하며 링크 초대는 별도 결정한다.

## 8. 에셋과 프론트 구현 범위

실제 3D 대신 아이소메트릭 2D를 우선안으로 한다. 배경 1개, 기능 에셋 4개, 캐릭터 기본·완료 2개 모습, 기본 기념품부터 제작한다. 글꼴은 SUIT 우선안, 기존 진한 보라색과 연한 라벤더를 유지한다.

이미지는 같은 각도·크기 기준·그림자 방향으로 제작하고 기능 에셋은 투명 PNG 등을 사용한다. 첫 버전은 지정된 슬롯에 배치한다. 슬롯은 벽·바닥·선반 등 종류별로 허용 에셋을 정하고 한 슬롯에는 하나만 놓는다. 자유 이동, 회전, 방 확장, 캐릭터 이동은 제외한다.

설치된 기능과 방 배치는 별도로 관리한다. 에셋 외형을 바꾸거나 기념품을 이동해도 기능 데이터는 바뀌지 않는다. 클라이언트가 클릭 좌표나 이미지 경로만으로 기능 접근 권한을 결정하지 않는다.

## 9. 백엔드 데이터와 처리 구조 제안

| 데이터 | 핵심 내용 |
|---|---|
| Space / SpaceMember | 공간, 구성원, 역할, 가입 상태 |
| Invitation | 초대 대상, 상태, 유효 기간 |
| SpaceModule | 공간별 모듈, 활성·숨김 상태 |
| AssetDefinition / RoomPlacement | 에셋 종류, 연결 모듈, 슬롯, 배치 버전 |
| Schedule / Task / Activity | 일정, 일회성 할 일, 활동과 완료 상태 |
| RepeatRule | 주기, 담당자, 시작일, 상태, 버전 |
| RepeatOccurrence | 규칙, 예정일, 담당자 스냅샷, 완료자·완료 시각 |
| FootPrint / Photo / Contribution | 활동 기록, 사진, 구성원 후기, 게시 상태 |

주요 무결성 조건은 공간·모듈 조합, 공간·슬롯 조합, 반복 규칙·예정일 조합, 활동·Foot Print 조합의 중복 방지다. 회차 완료 정보는 실제 처리자가 남아야 한다.

반복 생성 작업은 매일 수행하고 활성 규칙별 처리 기준 날짜를 저장한다. 배치 장애로 빠진 활성 기간의 회차를 재생성할 수 있게 하되, 일시정지 기간은 제외한다. 재시도해도 중복되지 않도록 DB 제약을 둔다. 화면의 다음 예정은 규칙으로 계산한 예고이며 아직 생성되지 않은 회차를 완료할 수는 없다.

방 저장은 버전 번호를 사용한다. 두 관리자가 동시에 변경하면 먼저 저장한 결과를 보존하고 나중 요청에는 최신 배치를 확인하도록 안내한다. MVP는 실시간 공동 편집 없이 저장 시 충돌 감지부터 구현한다.

모듈 활성화와 기본 에셋 배치, 활동 완료와 기록 초안 생성은 각각 일관된 결과가 되도록 처리한다. 사진은 공간 멤버의 접근 권한을 검증하고 업로드 실패·연결되지 않은 파일·삭제 시 파일 정리 정책을 둔다. 파일 형식과 용량 한도는 구현 전 별도 확정한다.

## 10. 개발 순서와 완료 기준

1. **공간 기반:** 인증, 공간 목록·생성·초대·역할 관리. 비멤버가 공간 데이터에 접근할 수 없는지 검증한다.
2. **기능과 방:** 모듈 추가·숨김, 고정 슬롯 배치, 기능 패널. 숨긴 도구를 다시 추가해도 데이터가 유지되는지 검증한다.
3. **반복 할 일:** 규칙, 회차 생성, 담당자 완료, 캐릭터 반응. 월말·배치 재시도·규칙 변경·정지와 재개·탈퇴 처리를 검증한다.
4. **활동 기록:** 활동 완료, Foot Print 초안·사진·후기·기념품. 중복 완료 요청과 접근 권한을 검증한다.
5. **사용성 확인:** 관계가 다른 사용자들이 기능을 구성하고, 물건 또는 바로가기로 일을 찾아 처리할 수 있는지 확인한다.

각 단계는 다음 단계 없이도 이용할 수 있는 상태로 완료한다. 기간과 인원은 아직 정하지 않았으므로 일정 추정은 별도 수행한다. 화면 변경은 시안을 먼저 공유하고 승인 후 애플리케이션에 반영한다.

## 11. 검증 지표와 남은 결정

초기에는 공간 생성 후 도구 구성 완료 여부, 초대받은 구성원의 첫 기능 사용, 반복 할 일 실제 완료, 서로 다른 관계의 기능 구성 차이, 완료 활동의 기록 작성 여부를 관찰한다. 방 꾸미기 클릭 수만으로 가치를 판단하지 않는다. 목표 수치는 사용자 테스트 이후 정한다.

구현 전 결정할 사항:

- 첫 사용자 그룹과 그 그룹에서 필요한 초기 모듈.
- 제안한 MVP 4개 모듈의 범위와 Foot Print 개발 순서.
- 권한 정책, 고정 슬롯 수, 초대 방식.
- 캐릭터와 에셋의 최종 스타일 및 제작·사용 권리.
- 사진 저장 방식·한도·삭제 정책.
- 반복 규칙의 날짜 정책과 알림 추가 시점.

현재 문서는 서비스 방향과 구현 가능한 첫 범위를 정리한 초안이다. 방 꾸미기의 규모보다 관계별 도구 선택과 반복 업무 처리의 효용을 먼저 검증한다.
