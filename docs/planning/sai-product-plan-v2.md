## 요약

SAI는 함께한 활동의 기록이 쌓여 우리만의 방이 되는 공유 공간이다. MVP의 목표는 "활동 → 기록 → 기념품" 흐름 하나를 멤버 모두가 같은 서버 데이터로 끝까지 쓰게 하는 것이다.

| 항목 | 내용 |
| --- | --- |
| 정의 | 관계마다 하나의 3D 방. 가구는 기능을 열고, 기념품은 기억을 연다 |
| 대상 | 연인, 친구, 동아리. 관계(누구와)와 테마(무엇을 좋아하나)를 따로 고른다 |
| 핵심 흐름 | 공간 만들기 → 링크로 모이기 → 활동 준비 → 완료 → Foot Print → 기념품 |
| 차별점 | 기능이 아니라 쌓인 기록. 시간이 지날수록 다른 앱으로 옮길 수 없는 방이 된다 |
| MVP | 활동·도구 서버 저장, 링크 초대, Foot Print, 기념품, 공간 색 |
| 지금 막힌 곳 | 활동·투표·정산이 만든 사람의 브라우저에만 저장되어 다른 멤버가 볼 수 없다 |
| 다음 단계 | 활동·도구 서버 저장부터 시작하고, 연인·친구·동아리 각 1팀으로 검증한다 |

## 서비스 정의와 문제

SAI는 도구 상자가 아니라 기록이 쌓이는 방이다. 일정·투표·정산 같은 도구는 그 기록을 만드는 준비 과정으로 둔다.

**문제** (가설이며 사용자 조사로 확인해야 한다)

- 모임의 일정, 투표, 정산은 단톡방, 캘린더, 정산 앱에 흩어진다.
- 끝난 활동의 사진과 이야기는 단톡방 사진첩에 묻혀 다시 찾지 않는다.
- 기능 하나하나는 이미 무료 도구가 있어, 기능만으로는 옮겨 올 이유가 약하다.

**검증할 가설**

| 번호 | 가설 | 확인 방법 |
| --- | --- | --- |
| H1 | 활동을 끝내고 Foot Print를 남긴 모임은 다음 활동도 SAI에서 만든다 | 게시한 모임의 30일 안 두 번째 활동 생성 비율 |
| H2 | 기념품이 놓인 방은 다시 찾아올 이유가 된다 | 게시 2주 뒤 기념품·Foot Print 열람 |
| H3 | 모임의 정체성이 드러나는 방은 초대받은 사람의 첫 참여를 높인다 | 테마를 적용한 공간과 기본 공간의 초대 후 첫 사용 비교 |

## 대상 사용자: 관계 × 테마

공간을 만들 때 관계와 테마를 따로 고른다. 관계는 인원·권한·추천 도구·문구를 정하고, 테마는 겉모습만 정한다. "연인 + 등산", "친구 + 축구"처럼 자유롭게 조합하며, 관계 유형은 추천일 뿐 기능을 제한하지 않는다.

| 항목 | 연인 | 친구 | 동아리 |
| --- | --- | --- | --- |
| 인원 | 2명 | 4~8명 | 10~50명 |
| 기본 권한 | 둘 다 관리자 | 만든 사람 + 멤버 | 회장·운영진·부원 |
| 추천 도구 | 공유 달력, 기념일, 사진 앨범, 위시리스트 | 투표, 정산, 여행 일정, 준비물 | 일정, 공지, 회비, 출석 |
| 대표 기념품 | 1주년 액자, 여행 티켓 | 여행 기념품 | 대회 트로피, 기수 단체 사진 |
| 초대 문구 | 상대 초대하기 | 친구 초대하기 | 부원 초대하기 |
| 장점 | 한 명만 초대하면 시작 | 이미 만든 여행 도구를 바로 활용 | 활동이 잦고 기수별 기록이 이어짐 |
| 주의 | 기존 커플 앱과 경쟁 | 활동이 드물어 재방문 이유가 약함 | 인원이 많아 모으기 어렵고 테마 에셋이 많이 듦 |

**검토 후보** (MVP 제외)

- 가족: 반복 할 일과 고양이 캐릭터. v1의 MVP였으나 후순위로 옮긴다.
- 회사 팀: 워크숍, 회식, 프로젝트 마무리 기록. 업무 관리 도구와 경쟁하지 않는다. 사내 계정 연동과 보안 요구가 달라 별도로 검토한다.

**경쟁 위치**

| 대안 | 잘하는 것 | SAI가 다른 점 |
| --- | --- | --- |
| 단톡방 | 대화, 사진 공유 | 끝난 활동이 기록과 기념품으로 남는다 |
| 커플 앱 | 기념일, 사진, 대화 | 관계의 정체성이 드러나는 방과 기념품 |
| 캘린더·정산·투표 앱 | 각 기능의 완성도 | 기능이 한 공간 안에서 기록으로 이어진다 |
| 문서 도구 | 자유로운 정리 | 따로 정리하지 않아도 활동을 끝내면 쌓인다 |

## 핵심 경험 흐름

한 모임은 일곱 단계를 거쳐 방에 기념품을 하나 남긴다. 1~5단계는 지금 있는 도구를 서버로 옮기고 링크 초대를 더하면 되고, 6~7단계는 새로 만든다.

```text
1 공간 만들기 ──▶ 2 링크로 모이기 ──▶ 3 활동 만들기 ──▶ 4 함께 준비
  관계·테마·색       단톡방에 링크 공유      여행·경기·기념일    투표·준비물·정산
                                          ▲                     │
                                          │ 다음 활동            ▼
                    7 기념품 진열 ◀── 6 Foot Print 게시 ◀── 5 활동 완료
                      누르면 기록이 열림   사진·후기 모아 게시     초안 생성
```

6·7단계가 다른 앱에 없는 부분이다. 기념품이 다음 활동을 만드는 이유가 되는지가 가설 H1·H2의 핵심이다. 단계별 화면은 [room-workflow 시안](../mockups/room-workflow/index.html)에서 볼 수 있다.

## 방 구조: 가구는 기능, 기념품은 기억

방에는 두 층이 있다. 가구를 누르면 도구가 열리고, 기념품을 누르면 Foot Print가 열린다. 두 역할을 섞지 않아야 무엇이 열리는지 헷갈리지 않는다.

| 구분 | 가구 | 기념품 |
| --- | --- | --- |
| 여는 것 | 도구(일정, 할 일, 정산, 투표 등) | Foot Print(사진, 후기, 기간, 참여자) |
| 생기는 때 | 도구를 설치할 때 | 활동을 끝내고 기록을 게시할 때 |
| 놓는 곳 | 바닥 8×8 칸 | 선반·탁자 위 자리, 벽 |
| 외형 | 에셋 목록에서 선택, 테마에 따라 바뀜 | 물건형 3D 또는 사진·그림형 받침대 |

### 기념품 고르기

Foot Print를 게시하면 두 탭 중에서 고른다.

1. **물건**: 3D 기념품 목록에서 고른다. 활동 유형과 태그로 먼저 추천한다(바다 여행이면 조개, 등대).
2. **사진·그림**: 아크릴 스탠드, 폴라로이드, 액자 중 하나를 고르고 넣을 사진을 고른다. 생성 일러스트는 후순위다.

### 방이 공간마다 달라지는 3단계

| 시점 | 무엇이 다르게 만드나 |
| --- | --- |
| 첫날 | 공간 색: 두 원의 색이 벽 띠, 소파, 러그에 들어간다 |
| 쓰는 동안 | 설치한 도구: 도구마다 대응하는 가구가 놓인다 |
| 시간이 지나면 | 기념품: 끝낸 활동마다 하나씩 쌓인다 |

### 진열과 보관

- 방 하나에 놓을 수 있는 요소는 64개다(현재 서버 검증 기준).
- 진열한 기념품만 방에 두고, 나머지는 기념품 보관함에 둔다.
- 기념품을 치워도 Foot Print는 남는다. 기억은 지우지 않고 진열만 바꾼다.

## 테마와 에셋 체계

에셋은 한 번 만들면 모든 테마에서 쓰고, 테마는 한 번 만들면 모든 에셋에 적용된다. 에셋 40개와 테마 8개라면 320번이 아니라 48번 만든다.

### 공통 뼈대

모든 테마는 8×8 바닥, 벽 두 면, 정해진 선반·벽 자리를 공유한다. 테마는 벽, 바닥, 창문, 조명, 색만 바꾸므로 테마를 바꿔도 배치가 유지된다.

### 색 역할

| 역할 | 테마에 따라 | 예시 |
| --- | --- | --- |
| 주색 | 바뀜(공간의 첫 번째 원 색) | 소파 천, 쿠션 |
| 보조색 | 바뀜(두 번째 원 색) | 화분, 받침대 |
| 재료색 | 테마 톤에 맞춰 조금 바뀜 | 나무, 금속, 유리 |
| 고유색 | 바뀌지 않음 | 귤의 주황, 잎의 초록 |

테마마다 조명 색도 다르게 해서, 고유색 물건도 방의 톤에 섞이게 한다.

### 관심사 테마 팩 예시: 축구

| 층 | 내용 |
| --- | --- |
| 색 | 팀 유니폼 색을 두 원 색으로 사용 |
| 껍데기 | 잔디 러그, 창밖 운동장, 벽 페넌트 |
| 기능 가구 | 일정 → 전술판, 투표 → 라커룸 게시판, 정산 → 회비 저금통, 준비물 → 장비 가방 |
| 기념품 | 대회 트로피, 날짜를 적은 경기 공, 메달, 단체 사진 |
| 사용자 업로드 | 동아리 엠블럼과 이름을 페넌트·유니폼 액자에 넣음 |

실제 프로팀 로고는 기본 에셋에 넣지 않는다.

### 에셋 목록 파일

에셋 종류를 코드 대신 목록 파일 하나로 관리하고, 프론트엔드와 백엔드가 같은 파일을 읽는다. 에셋 추가는 파일을 넣고 목록에 한 줄 쓰는 일이 된다.

항목: id, 파일, 이름, 분류(가구·기념품), 태그, 놓는 곳(바닥·선반·벽), 크기, 재질별 색 역할, 라이선스, 출처.

### 확보 방법과 기준

| 방법 | 쓰임 | 기준 |
| --- | --- | --- |
| CC0 에셋 팩(Kenney, Quaternius, KayKit 등) | 모양이 복잡한 물건 | 둥근 로우폴리·무광, 색을 다시 칠할 수 있는 모델만 |
| 코드로 만든 형태 | 조개, 병, 표, 트로피처럼 단순한 물건 | 지금 방과 같은 둥근 상자·구 |
| 3D 받침대 + 2D 내용물 | 사진, 생성 일러스트, 엠블럼 | 카메라가 고정이라 납작한 판이 어색하지 않음 |
| AI 3D 생성 | 시안·실험 | 폴리곤 수·스타일·이용 약관 문제로 제품 에셋에는 쓰지 않음 |

첫 버전 수량은 기념품 30~40개, 사진 받침대 3개, 테마 팩 1개(축구)다. 이후에는 목록 파일에 추가해 늘린다.

## 권한 정책

모든 권한은 서버에서 검사한다. 관계를 고르면 기본 역할이 정해지고, 소유자가 언제든 바꿀 수 있다.

| 작업 | 소유자 | 관리자 | 멤버 |
| --- | --- | --- | --- |
| 공간 조회, 활동·할 일·일정 작성 | 가능 | 가능 | 가능 |
| 사진·후기 작성 | 가능 | 가능 | 가능 |
| 초대 링크 만들기·폐기 | 가능 | 가능 | 불가 |
| 도구 설치·숨김, 방 배치, 공간 색·테마 | 가능 | 가능 | 불가 |
| Foot Print 게시, 기념품 진열·보관 | 가능 | 가능 | 활동을 만든 사람만 |
| 다른 사람의 콘텐츠 수정·삭제 | 가능 | 가능 | 불가 |
| 역할 변경, 소유권 이전, 공간 삭제 | 가능 | 불가 | 불가 |

**관계별 기본값**

- 연인: 초대받은 사람도 관리자가 된다.
- 친구: 만든 사람이 소유자, 나머지는 멤버다.
- 동아리: 회장이 소유자이고, 운영진을 관리자로 지정한다.

멤버는 자신이 작성한 콘텐츠를 수정·삭제할 수 있다. 마지막 소유자는 소유권을 넘기기 전에는 탈퇴할 수 없다.

## MVP 범위

MVP는 한 모임이 활동을 준비하고, 끝내고, 기념품을 남기는 흐름을 멤버 모두가 같은 데이터로 쓰는 것이다.

**포함**

- 관계 설정 3종(연인, 친구, 동아리)과 링크 초대
- 활동과 기존 도구(일정, 준비물, 정산, 투표, 기록, 할 일)의 서버 저장
- Foot Print: 완료하면 초안이 생기고, 여러 멤버가 사진·후기를 더한 뒤 확인하고 게시
- 기념품: 물건형 30~40개, 사진 받침대 3종, 진열과 보관함
- 공간 색(프리셋 8쌍), 에셋 목록 파일 전환

**2차**

- 축구 테마 팩, 동아리 엠블럼 업로드

**제외**

- AI 일러스트·3D 생성, 반복 할 일, 실시간 공동 편집, 지도 검색 API, 실제 송금
- 가족·회사 팀 관계, 방 구조가 바뀌는 테마 여러 종

## 현재 구현 상태

공간과 초대, 방 배치는 서버에 있지만 활동과 도구는 만든 사람의 브라우저에만 저장된다. 그래서 지금은 핵심 흐름의 세 번째 단계에서 멤버 간 공유가 끊긴다. 기준은 2026년 11월 4일, 커밋 `a254257`이다.

| 영역 | 상태 | 내용 |
| --- | --- | --- |
| 회원가입·로그인·세션 | 멤버 공유 | BCrypt 비밀번호 해시, 세션 쿠키 |
| 공간·역할 | 멤버 공유 | 생성, 목록, 소유자·관리자·멤버 |
| 초대 | 멤버 공유 | 아이디 검색, 보내기, 받은 초대함 수락·거절 |
| 방 배치 | 멤버 공유 | 3D 방에서 8×8 배치, 버전 충돌 감지, 멤버 편집 차단 |
| 활동·기록·할 일·일정 | 브라우저만 | 새로고침 후 유지, 다른 멤버에게 보이지 않음 |
| 여행 일정·준비물·정산·투표 | 브라우저만 | 균등 분담과 정산 제안 포함 |
| 가구와 활동 연결, 낮·저녁 | 브라우저만 | 배치는 서버, 연결 정보와 조명 설정은 로컬 |
| 링크 초대 | 없음 | 미착수 |
| Foot Print·사진 업로드 | 없음 | 사용 흐름 시안만 있음 |
| 기념품·공간 색·테마 | 없음 | 색·기념품 시안만 있음 |

**알려진 문제**

- 가구 종류 8개가 프론트엔드(`frontend/src/features/room/model.ts`)와 백엔드(`RoomLayoutValidator.java`) 코드에 각각 고정되어 있어, 에셋을 늘리려면 구조 변경이 필요하다.
- 같은 초대를 동시에 수락하면 DB 제약 위반이 처리되지 않아 500 응답이 난다.
- 대기 중인 중복 초대를 막는 DB 제약이 없고, 역할별 초대 권한이 정해지지 않았다.
- 프론트엔드 E2E 테스트는 모의 API 기준이며, 모바일 GPU 성능은 검증하지 않았다.

## 개발 로드맵

첫 단계는 활동·도구 서버 저장이다. 이 단계가 없으면 이후에 만드는 기능도 만든 사람에게만 보인다. 화면이 바뀌는 단계는 시안을 승인받은 뒤 구현한다.

1. **정리**: 초대 동시성, 중복 제약, 예외 응답, 문서 정합성.
    - 완료 기준: 동시 수락과 중복 초대가 500이 아닌 409로 응답한다.
2. **활동·도구 서버 저장**: 활동, 일정, 준비물, 정산, 투표, 기록, 할 일.
    - 완료 기준: 다른 멤버 계정에서 같은 내용이 보이고, 권한과 수정 충돌을 검사한다. 기존 브라우저 데이터는 명시적으로 가져온다.
3. **링크 초대**
    - 완료 기준: 단톡방 링크로 가입한 뒤 바로 공간에 들어오고, 만료·폐기가 동작한다.
4. **에셋 목록 파일 전환** (2~3단계와 병행 가능)
    - 완료 기준: 프론트엔드와 백엔드가 같은 목록을 쓰고, 기존 배치가 그대로 열린다.
5. **Foot Print와 사진 업로드**
    - 완료 기준: 완료하면 초안이 생기고, 여러 멤버가 사진·후기를 더하며, 게시 전에 확인한다. 저장 위치·용량·삭제 정책이 적용된다.
6. **기념품·진열·공간 색**
    - 완료 기준: 기념품을 누르면 Foot Print가 열리고, 보관함이 동작하며, 다른 멤버도 같은 방을 본다.
7. **관계 설정 3종**
    - 완료 기준: 관계별 기본 권한, 추천 도구, 문구가 적용된다.
8. **사용자 테스트**
    - 완료 기준: 연인 1쌍, 친구 1팀, 동아리 1팀이 핵심 흐름을 끝까지 사용한다.

축구 테마 팩은 8단계 결과를 보고 2차로 만든다. 단계별 일정은 인원이 정해지면 따로 추정한다.

## 성공 지표

기록을 남기고 다시 찾아오는지를 본다. 목표 수치는 첫 사용자 테스트 뒤에 정하고, 방 꾸미기 클릭 수는 기준으로 쓰지 않는다.

| 지표 | 정의 | 연결된 가설 |
| --- | --- | --- |
| 초대 후 첫 사용 | 초대받은 사람 중 7일 안에 도구를 한 번 이상 쓴 비율 | H3 |
| 기록 게시율 | 완료한 활동 중 Foot Print를 게시한 비율 | H1 |
| 기념품 재방문 | 게시 2주 뒤 기념품이나 Foot Print를 다시 연 공간 비율 | H2 |
| 두 번째 활동 | 첫 활동 완료 후 30일 안에 새 활동을 만든 공간 비율 | H1 |
| 관계별 차이 | 위 지표를 연인·친구·동아리로 나눠 비교 | 다음 투자 대상 결정 |

## 위험과 대응

가장 큰 위험은 모임 전원이 가입해야 가치가 생기는 구조다. 링크 초대와 2명으로 시작하는 연인 테스트로 먼저 대응한다.

| 위험 | 대응 |
| --- | --- |
| 모임 전원이 가입해야 가치가 생김 | 링크 초대, 연인처럼 작은 관계부터 검증 |
| 기능 단위로는 기존 앱을 이기기 어려움 | 기능 확장 대신 기록 흐름 완성에 집중 |
| 에셋 스타일이 섞여 어색함 | 골라 담기 기준, 색 역할, 같은 조명 |
| 사진의 개인정보와 저장 비용 | 자동 공개 없음, 게시 전 확인, 용량 한도, 삭제 정책 |
| 모바일에서 3D 성능 | 진열 한도, 방에 놓인 에셋만 불러오기, 실제 기기 검증 |
| 저작권 | CC0 에셋 우선, 라이선스를 목록 파일에 기록, 프로팀 로고 제외 |
