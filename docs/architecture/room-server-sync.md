# 방 화면의 맵 서버 연동

2026-10-11. 승인한 [시안과 검증안](../mockups/room-server-sync/design.md)을 구현했다.
기존 맵 저장 API·JSONB 스키마는 변경하지 않았다.

## 현재 동작

- 방 진입 시 GET `/api/spaces/{spaceId}/room`으로 배치와 수정 버전을 조회한다.
- OWNER/MANAGER만 편집·가져오기·저장할 수 있다. MEMBER에는 편집 버튼을 표시하지 않는다.
- 미저장 공간과 저장된 빈 배치에는 기본 가구를 자동 생성하지 않는다.
- PUT은 마지막 조회/저장 버전을 사용한다. 저장 중 입력·가구 이동·중복 저장·일반 화면 이동을 차단한다.
- 실패 시 초안을 유지한다. 401은 기존 인증 만료 흐름에 전달하고 403은 권한 오류를 표시한다.
- 409는 저장을 차단한다. 최신 배치를 조회해 미리 볼 수 있지만 내 초안을 덮어쓰거나 PUT을 자동 재시도하지 않는다.
- 최신 배치로 새 편집을 시작할 때 사용자 확인 후 기존 초안을 로컬 백업한다. 변경은 새 배치에 직접 다시 적용한다.
- 이전 공간의 조회 응답은 취소·요청 번호·unmount 검사로 현재 공간에 반영되지 않는다.

## 데이터 변환과 개인 연결

`server.ts`가 서버 DTO와 Furniture 사이를 변환한다. w/h는 종류·회전으로 복원하고 서버에 전송하지 않는다.
서버 응답의 공간 ID·안전한 정수 버전·격자·UUID·가구 배치를 검사한다.

활동은 아직 로컬 ID를 사용한다. 활동에 연결한 가구의 event/module/label은 계정·공간·가구 ID별 로컬 sidecar에 보존한다.
그 가구의 공용 module/label은 비워 다른 멤버에게 장식으로 표시한다. 같은 브라우저·계정에서는 활동 연결을 복원한다.
공간 전체에 연결한 module/label은 공유하지만 실제 도구 내용은 여전히 각 브라우저에 있다.
낮/저녁 설정도 개인 로컬 설정이다. 서버 콘텐츠 공유나 실시간 동기화가 추가된 것은 아니다.

## 가져오기·실패 복구

- 기존 `sai:room:v1:<loginId>:<spaceId>` 원본은 삭제하지 않는다. 명시적으로 가져오면 초안으로 열고, 저장 버튼을 눌러야 업로드한다.
- 손상된 기존 배치는 가져오지 않고 보존한다. 이 경우 정상 서버 배치의 편집은 계속 가능하다.
- `sai:room-bindings:v1`은 개인 활동 연결 저장소다. 손상된 연결 정보를 조용히 덮어쓰지 않고 저장을 막는다.
- PUT 전에 `sai:room-draft:v1`에 버전과 전체 초안을 기록한다. 이 쓰기에 실패하면 PUT하지 않는다.
- 서버 저장 후 sidecar 확정에 실패하면 부분 성공을 알리고 초안을 남긴다. 다시 조회해 서버 배치가 초안과 일치하고 서버 버전이 증가했으면 개인 연결을 복구한다. PUT을 다시 보내지 않는다.
- 그 외 복구 초안은 명시적으로 가져올 수 있다. 초안 버전과 서버 버전이 다르면 충돌 처리부터 시작한다.
- 최신 배치로 전환하기 전 백업은 `sai:room-draft:v1:…:backup:<uuid>`에 남는다. 현재 별도 백업 목록 UI는 없고 브라우저 저장소에서 확인할 수 있다.
- 브라우저 데이터 삭제·저장소 차단 상태까지 초안 보존을 보장하지는 않는다. 강제 페이지 종료로 PUT 응답이 유실될 때는 다음 조회와 복구 기록으로 확인한다.

## 검증과 시안 차이

타입 검사·빌드, 단위 테스트 24개, Chromium 전체 E2E 46개, 백엔드 테스트 58개가 통과했다.
변경 파일의 ESLint·oxlint를 확인했다. 기존 3D 엔진의 번들 크기 경고는 남아 있다.

단위 테스트는 서버 변환·회전 크기·공용/개인 연결 분리·응답 검증·저장 실패·복구 기록·원본 보존을 검사한다.
프런트 E2E는 빈 배치, OWNER/MANAGER/MEMBER, 가져오기, 활동 연결의 계정 분리, 재조회,
409 비교·확인, 네트워크 실패, 저장소 실패, 부분 성공, 중복 저장·이탈 방지, 이전 공간 응답 무시, 401/403을 검사한다.

`RoomIntegrationTest.realHttpSessionsSearchInviteJoinAndShareRoom`은 임의 포트의 실제 Spring 서버와 독립 쿠키 세션 두 개를 사용한다.
가입→로그인→검색→초대→수락→맵 저장→다른 멤버 조회를 실제 HTTP로 수행하고 MEMBER의 PUT 403과 오래된 PUT 409를 확인한다.
DB는 개발 데이터와 분리한 테스트 스키마에 Flyway를 적용하며 테스트 후 삭제한다.
이 HTTP 테스트에는 Vue 브라우저가 포함되지 않는다. Vue E2E는 모의 API이므로 서로 증거 범위를 구분한다.

시안과의 차이: 기존 3D 렌더러·가구 미리보기·격자·상단 탐색을 유지했다. 충돌 비교는 최신 배치와 내 초안을 전환해서 보며,
시안의 비교 요약 카드 대신 안내와 전환 버튼을 사용한다. 오류 재시도는 기존 저장 버튼 또는 다시 불러오기 버튼으로 제공한다.
