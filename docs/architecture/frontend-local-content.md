# 프론트 임시 데이터와 백엔드 연결 준비

인증·공간 생성·공간 목록·사용자 초대는 기존 API를 유지한다. 새 세부 기능은 `frontend/src/features/content`에 구현하고 브라우저 저장소를 사용한다. 실제 서버 멤버나 역할 권한을 흉내 내어 저장하지 않는다.

## 경계와 데이터

- `types.ts`: 활동, 기록, 할 일, 약속, 장소, 준비물, 지출, 투표와 참여자의 타입.
- `repository.ts`: `ContentRepository.load(owner, spaceId, name)` / `save(owner, spaceId, state)` 비동기 경계. 현재 구현은 `BrowserContentRepository`.
- `useContent.ts`: 초기 로드, 처리 중 상태, 저장 오류와 성공 안내. 복제본을 저장한 뒤 화면 상태를 교체하므로 저장 실패가 기존 데이터를 덮어쓰지 않는다.
- `logic.ts`: 날짜·기간·좌표·투표 마감·참여자·정산의 공통 검증.
- `SpaceContent.vue`: 화면과 사용자 동작. `HomeView.vue`에서 실제 계정·공간 정보를 전달하고 기존 초대 화면을 슬롯으로 제공한다.

키는 `sai:content:v1:<URL 인코딩한 로그인 아이디>:<공간 ID>`이며 상태 버전은 1이다. `eventId: null`은 공간 소속, 문자열은 활동 소속이다. 활동은 소속 기능 ID와 참여자 ID를 따로 가진다. 공간을 최초로 열면 체험 여행·모임·콘텐츠를 생성한다. 현재 사용자와 예시 인물을 명시적으로 구분하며 실제 서버의 참여 인원과 체험 인원이 다를 수 있다.

## 동작·검증 기준

- 보관 활동의 수정은 화면 버튼과 저장 직전 검증에서 막는다. 보관 해제는 가능하다.
- 기록은 수동 저장이며 변경된 제목·본문이 있으면 이동과 로그아웃 전에 확인한다.
- 저장 공간 부족·저장소 차단·손상된 데이터·지원하지 않는 버전은 오류로 안내한다. 손상 데이터를 자동 초기화하거나 덮어쓰지 않는다.
- 날짜는 ISO 날짜를 검증하고 현재 날짜와 투표 마감은 한국 시간 기준이다. 여행 날짜 목록은 최대 366일까지 표시한다.
- 정산은 양의 원화 정수와 선택한 수혜자의 균등 분담이다. 나머지 원은 고정된 참여자 ID 순서로 1원씩 배분한다. 실제 송금 기능은 없다.
- 지출에 사용된 참여자 제거를 막는다. 그 외 제거한 참여자의 할 일·준비물 담당은 미지정으로 바뀐다.
- 투표 선택지는 중복 없이 2~8개다. 현재 사용자의 한 표를 변경할 수 있으며 수동 또는 지정 시각 마감 후 변경을 막는다.
- 지도·AI 호출·실시간 전송은 하지 않는다. 향후 기능 설명은 고정 예시다.

## 서버 연결 시 남은 작업

저장소 경계는 교체할 수 있지만 현재 `save`는 공간 콘텐츠 전체 스냅샷을 받는다. 실제 서버에서 모듈별 API를 제공한다면 변경 사항을 작업 단위로 나누거나 어댑터에서 차이를 계산해야 한다. 다음 계약이 필요하다.

1. 서버 활동·콘텐츠 ID와 클라이언트 임시 ID 대응, 생성 응답 반영.
2. 실제 멤버 목록·역할과 예시 참여자 분리, 서버에서 공간/활동 접근 권한 검증.
3. 생성·수정·완료·보관·투표의 요청과 오류 계약. 중복 요청 방지와 낙관적 버전 검증.
4. 서버 시간 기준 마감, 정산 금액 검증과 일관된 반올림 규칙.
5. 브라우저 임시 데이터의 수동 이관·충돌·실패 처리. 지금은 자동 업로드하지 않는다.
6. 동시 수정 시 충돌 해결과 여러 탭/사용자의 갱신 전파. 현재는 마지막 저장이 우선하며 실시간 협업을 지원하지 않는다.
