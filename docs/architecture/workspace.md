# 작업 공간 기능의 구조와 정책

2026-11-05에 추가한 공유 콘텐츠, 멤버 관리, 초대 링크, 공지·댓글, 소식·알림, 사진첩, Foot Print·기념품, 계정 관리의 구조입니다. 백엔드는 `backend/src/main/java/com/sai/backend/workspace`, 스키마는 `V5__workspace_foundation.sql`입니다.

## 공유 콘텐츠

- 활동과 도구(기록, 할 일, 일정, 여행 일정, 장소, 준비물, 정산, 투표, 기념일, 위시리스트, 회비, 출석, Foot Print)는 공간마다 JSON 문서 하나(`space_content`)로 저장합니다. 기존 화면이 상태 전체를 읽고 쓰는 구조라 화면을 그대로 두고 저장 위치만 서버로 옮길 수 있었습니다.
- 저장할 때 읽어 온 `version`을 보냅니다. 다른 멤버가 먼저 저장했으면 409(`CONTENT_VERSION_CONFLICT`)를 받고, 프론트(`useContent.commit`)가 최신 문서를 다시 받아 **같은 변경 함수**를 한 번 더 적용합니다. 최대 3번 시도합니다.
- 다른 멤버의 변경은 45초마다, 그리고 탭으로 돌아올 때 조용히 다시 불러옵니다. 실시간 동기화는 아닙니다.
- 멤버 id는 서버 문서에서 `u<userId>`이고, 화면에서는 지금 사용자를 계속 `self`로 부릅니다. 변환은 `contentSync.ts`의 `mapMemberIds`가 담당합니다. 나간 멤버는 "(나감)"을 붙여 기록이 계속 읽히게 남깁니다.
- 저장할 때 이전 상태와 비교해 "투표를 추가했습니다: 숙소" 같은 한 줄을 만들어 소식으로 보냅니다(`describeChange`).
- 서버는 문서가 `version: 1` 객체인지와 크기(200만 자)만 검사합니다. 항목 단위 권한(예: 남의 기록 수정 금지)은 아직 없습니다. 멤버 누구나 모든 항목을 고칠 수 있다는 점이 MVP의 한계입니다.

## 멤버·공간 관리

- 소유자는 역할을 바꾸고, 다른 멤버를 소유자로 지정하면 자신은 관리자가 됩니다. 관리자는 멤버만 내보낼 수 있습니다.
- 소유자는 다른 멤버가 있으면 나갈 수 없고(`OWNER_MUST_TRANSFER`), 마지막 멤버가 나가면 공간이 삭제됩니다. 공간을 삭제하면 사진 파일도 지웁니다.
- 공간 가입은 DB 트리거가 함께 처리합니다. 연인 공간이면 MEMBER를 MANAGER로 바꾸고, 같은 공간에 온 다른 대기 초대를 닫고, "○○님이 들어왔습니다" 소식을 남깁니다. 아이디 초대와 링크 초대가 같은 규칙을 따릅니다.
- 같은 초대를 동시에 수락하거나 대기 중 초대를 중복으로 보내면 DB 제약에 걸리고 409(`ALREADY_PROCESSED`)로 응답합니다.

## 초대 링크

- 24바이트 난수 토큰, 7일 유효, 소유자·관리자만 만들고 폐기합니다.
- 미리보기(`GET /api/invite-links/{token}`)는 로그인 없이 공간 이름·인원·초대한 사람을 보여 줍니다. 로그인하지 않은 사람은 로그인이나 가입을 거친 뒤 같은 링크로 돌아옵니다. 돌아갈 주소는 앱 내부 경로만 허용합니다.

## 소식·알림·배지

- `space_feed` 한 테이블이 공간 최근 소식, 알림함, 안 읽은 수, 가구 배지를 모두 만듭니다.
- 안 읽음 = 다른 사람이 남겼고 내가 그 공간을 마지막으로 연 시각(`space_member.last_seen_at`) 이후에 생긴 소식입니다. 공간에 들어가면 읽음으로 바뀝니다.
- 같은 사람이 10분 안에 같은 문장을 남기면 하나로 합칩니다(여러 장 업로드, 연속 저장).
- 헤더와 공간 목록은 1분마다 `/api/spaces/overview`를 다시 받습니다. 푸시 알림은 없습니다.

## 사진

- 파일은 `sai.storage.dir`(`SAI_STORAGE_DIR`, 기본 `data/photos`) 아래 `<공간 id>/<uuid>.<확장자>`로 저장합니다. 경로는 클라이언트 값을 쓰지 않습니다.
- 형식은 파일 이름이 아니라 앞부분 바이트로 판별합니다(JPG, PNG, GIF, WEBP). 장당 10MB.
- 파일 응답은 멤버만 받을 수 있고 `Cache-Control: private`, `X-Content-Type-Options: nosniff`를 붙입니다.
- 썸네일 생성과 EXIF 위치 정보 제거는 아직 없습니다. 원본이 그대로 저장됩니다.

## Foot Print와 기념품

- 완료한 활동에서 Foot Print 초안을 만들고, 활동에 연결된 사진을 고르고, 멤버마다 한 줄 후기를 남깁니다. 게시할 때 기념품을 고릅니다.
- 기념품은 공유 콘텐츠에 저장되고, 3D 방 왼쪽 벽의 2단 선반(최대 8개)에 놓입니다. 사진형(폴라로이드·액자·아크릴 스탠드)은 고른 사진을 텍스처로 쓰고, 물건형은 엔진의 둥근 상자·구로 만듭니다(`souvenirMeshes.js`). 카메라가 고정이라 납작한 판도 어색하지 않습니다.
- 기념품을 누르면 그 활동의 홈이 열리고 Foot Print가 보입니다. 기념품이 8개를 넘으면 오래된 것부터 8개만 보입니다. 보관함 화면은 아직 없습니다.

## 계정

- 탈퇴하면 혼자 있는 공간은 삭제하고, 멤버십을 지우고, 이름·아이디·연락처를 비웁니다. 다른 사람이 볼 수 있는 댓글·사진은 "탈퇴한 사용자"로 남습니다. 탈퇴한 아이디는 검색에 나오지 않습니다.
- 비밀번호 찾기는 이메일 발송이 필요해 아직 없습니다.

## 검증

- 백엔드: `WorkspaceIntegrationTest` 6개를 포함해 64개 테스트가 실제 PostgreSQL에서 통과합니다.
- 프론트: 단위 테스트 28개(멤버 id 변환, 병합, 변경 요약 포함), 기존 Chromium E2E 59개가 통과합니다. 3D 테스트 2개는 소프트웨어 GPU에서 병렬로 돌리면 시간 초과가 나고 단독 실행하면 통과합니다.
- `frontend/scripts/live-flow.cjs`가 실제 서버에서 계정 두 개로 전체 흐름을 확인합니다.
