# 2026-10-06 SAI 개발 기록

## 관계별 공간과 가구에 연결하는 도구

- 관계마다 필요한 기능을 선택해 함께 사용하는 공간이라는 서비스 방향을 정리했다.
- 지속적인 공간 안에 여행·모임·스터디 등의 이벤트를 두고, 각 이벤트에 필요한 도구를 선택하는 구조를 유지했다.
- 방 꾸미기는 기능으로 들어가는 시각적인 입구로 사용한다. 가구 모양과 기능은 독립적이며, 설치한 도구를 어떤 가구에든 연결하거나 장식으로만 사용할 수 있다.
- 반복 할 일과 Foot Print는 현재 범위에서 제외했다. 일반 할 일, 직접 작성하는 기록, 일정, 정산, 투표 등의 기존 기능은 유지했다.
- 디자인 시안을 먼저 공유하고 승인 후 실제 프론트에 반영하는 협업 규칙을 `AGENTS.md`와 안내용 훅에 기록했다. 훅 파일의 존재만으로 활성화나 승인 검증을 보장하지는 않는다.

## 소개 페이지와 공간 화면

- 소개 페이지에서 로그인·회원가입으로 이동하고, 인증 후 내 공간으로 들어가는 흐름을 추가했다.
- 소개 페이지는 두 추상적인 원이 접근하면서 닿기 전에 물방울처럼 연결되는 움직임을 표현했다.
- 내 공간은 이미지·이름·멤버 수·역할·들어가기로 구성한 목록을 세로로 배치했다.
- 공간 내부는 방을 중심으로 두고, 이벤트와 도구에 가구 또는 바로가기로 접근하도록 구성했다.
- Virtual Cottage 2의 공개 화면을 분위기 참고로 삼아 원목·크림·보라색 계열의 따뜻한 화면으로 정리했다. 해당 게임의 에셋은 사용하지 않았다.

## 실제 3D 방 구현

- Vue의 `RoomBoard.vue`에서 배치 초안·선택·회전·기능 연결·저장을 관리하고, `RoomCanvas.vue`에서 렌더러를 연결했다.
- Three.js 엔진은 공간 홈에 들어갈 때 지연 로딩한다. 초기 소개·인증 화면에 3D 엔진 전체를 포함하지 않는다.
- 직교 카메라로 고정된 아이소메트릭 시점을 사용하며, 바닥 평면 레이캐스팅으로 포인터를 8 × 8 격자 좌표로 변환한다.
- 가구마다 점유 칸을 지정하고, 드래그·방 밖 배치 거절·겹침 검사·90도 회전을 구현했다. 회전하면 점유 칸의 가로와 세로도 바뀐다. 러그는 다른 가구와 겹칠 수 있다.
- 무광 재질, 높이에 따른 따뜻한 색조 셰이더, 크림·살구색 주광, 보라색 보조광, PCF 부드러운 그림자와 ACES 톤 매핑을 적용했다.
- 낮/저녁 선택과 실제 모델을 렌더링한 가구 미리보기를 제공한다. 화면이 바뀔 때 렌더링하고, 화면 종료 시 이벤트·관찰자·생성 리소스를 정리한다.
- Three.js는 MIT, Kenney Furniture Kit 모델은 CC0다. 사용하는 GLB 10개와 라이선스만 포함했다. 방 구조·고양이·액자·달력은 기본 도형으로 구성했다.

## 데이터와 백엔드 경계

- 이번 작업에서 백엔드 코드와 DB 스키마는 변경하지 않았다. 회원가입·로그인·공간 생성·목록·초대는 기존 API를 사용한다.
- 가구는 `sai:room:v1:<encoded-loginId>:<spaceId>`, 분위기는 `sai:room-time:<encoded-loginId>` 키로 브라우저에 저장한다.
- 이벤트와 세부 도구는 기존 프론트 콘텐츠 저장소를 사용한다. 다른 사용자나 기기로 동기화되지 않는다.
- 배치 저장이 실패하면 편집 초안을 유지하고, 저장하지 않은 변경이 있을 때 공간 이동·로그아웃·페이지 종료를 확인한다.
- 실제 API 연결 시 현재 CORS 설정에 맞춰 `http://localhost:5173`으로 접속한다.

## 독립 목업과 README 정리

- `docs/mockups/room-interactive` 목업에 같은 3D 모델·격자·회전·조명·도구 연결을 반영했다. 목업은 로그인 없이 예시 데이터로 실행한다.
- 가구 연결 목록을 선택한 공간 또는 이벤트에 설치된 도구로 제한했다. 이벤트에는 장소·준비물도 연결할 수 있다.
- 배치를 저장할 때 이벤트 도구가 공간 전체에 자동 추가되던 동작을 제거했다. 연결한 이벤트의 도구가 사라지면 안내를 표시한다.
- 목업에서도 저장 실패 시 초안을 유지하고, 저장하지 않은 배치로 이동할 때 확인하도록 정리했다.
- 목업 데이터는 `sai-room-mock`, 분위기는 `sai-cottage-time`에 저장한다. 실제 계정 데이터와 분리하며 자동 이관하지 않는다.
- 루트·프론트 README를 현재 화면 구조, 실행 명령, API와 브라우저 저장의 구분, 에셋 라이선스에 맞게 갱신했다. 예전 디자인 자료는 이전 시안으로 구분했다.

## 승인된 로고 적용

- 세 가지 로고 방향을 비교하고 사용자가 선택한 **1안 ‘이어지는 사이’**를 적용했다.
- 두 형태가 부드럽게 이어지는 심볼과 직접 그린 소문자 `sai` 워드마크를 SVG 경로로 구성했다. 글꼴 설치에 따라 로고 형태가 달라지지 않는다.
- 기본 보라색, 어두운 배경용 밝은 로고, 작은 심볼을 준비했다.
- 공통 `AppLogo.vue`, 소개·로그인·회원가입·공간 화면, 목업 헤더, README 이미지와 SVG 브라우저 아이콘에 반영했다. 사용하지 않는 이전 ICO와 로고 CSS를 정리했다.
- 목업은 낮에 기본 로고, 저녁에 밝은 로고를 표시한다.
- `docs/assets/README.md`에 색상·사용 위치와 에셋 사본을 함께 갱신해야 하는 규칙을 기록했다.

## 검증 결과와 한계

- Vue 타입 검사와 프로덕션 빌드가 통과했다. 3D 엔진의 약 607 kB 지연 로딩 청크에 대한 Vite 크기 경고는 남아 있다.
- 3D 구현 단계에서 단위 검사 18개와 Chromium 콘텐츠·요청 계약·3D 화면 검사를 확인했다. 드래그, 경계·충돌 검사, 회전 저장·새로고침, 취소, 공간별 분리, 가구에서 이벤트 도구로 이동, 모바일 폭 배치를 검사했다.
- 로고 적용 후 기존 소개·인증·공간·초대 E2E 10개를 다시 실행해 모두 통과했다.
- 브라우저에서 실제 소개·로그인 로고, 목업의 낮/저녁 로고, 이벤트 연결 목록, 편집 취소, 저장·새로고침, 가구에서 정산·준비물 화면으로 이동하는 흐름을 확인했다.
- E2E는 모의 API 기반이며 실제 PostgreSQL 통합 검증을 대신하지 않는다. 실제 모바일 GPU 성능과 다중 사용자 동기화는 검증하지 않았다.
- 목업의 저장 용량 초과나 브라우저 종료를 강제로 발생시키는 검사는 수행하지 않았다.
