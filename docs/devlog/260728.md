### 1. UserRepository 구현 및 테스트

Spring Data JPA를 이용해 `UserRepository`를 작성했다.

```java
public interface UserRepository extends JpaRepository<User, Long> {

    Optional<User> findByLoginId(String loginId);

    boolean existsByLoginId(String loginId);
}
````

주요 내용:

* `JpaRepository<User, Long>` 상속
* 로그인 아이디로 사용자 조회
* 로그인 아이디 중복 여부 확인
* `Optional<User>`를 이용한 조회 결과 처리

`@SpringBootTest`를 이용해 실제 PostgreSQL 데이터베이스에 사용자를 저장하고 조회하는 테스트를 진행했다.

확인한 동작:

* 사용자 INSERT
* `loginId`를 이용한 사용자 SELECT
* `existsByLoginId()`를 이용한 존재 여부 조회
* JPA와 PostgreSQL 연동 정상 동작

기존 DB 연결 확인용 `CheckDBConnection`은 Repository 테스트가 완료되어 더 이상 필요하지 않게 되었다.

### 2. BCrypt 비밀번호 암호화 설정

`PasswordEncoder`를 Spring Bean으로 등록했다.

```java
@Configuration
public class PasswordConfig {

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

학습한 내용:

* `@Bean`은 메서드가 반환한 객체를 Spring 컨테이너에 등록한다.
* `@Autowired` 또는 생성자 주입으로 등록된 객체를 사용할 수 있다.
* BCrypt는 같은 비밀번호를 암호화해도 Salt 때문에 매번 다른 결과가 나온다.
* 비밀번호 비교는 암호화된 문자열끼리 비교하지 않고 `matches()`를 사용한다.

```java
passwordEncoder.matches(rawPassword, encodedPassword);
```

### 3. 회원가입 요청 DTO 작성

회원가입 요청 데이터를 받기 위한 `SignupRequest` record를 작성했다.

```java
public record SignupRequest(
        String name,
        String loginId,
        String password,
        String phoneNumber,
        String email
) {
}
```

DTO는 API 요청이나 응답에 필요한 데이터의 구조를 정의하는 객체이며, C/C++의 구조체와 비슷한 역할을 한다.

`record`를 사용하면 생성자와 데이터 접근 메서드가 자동으로 생성된다.

```java
request.loginId();
request.password();
```

### 4. 회원가입 요청값 검증 추가

Jakarta Validation을 이용해 회원가입 요청값 검증 규칙을 추가했다.

사용한 어노테이션:

* `@NotBlank`: null, 빈 문자열, 공백 문자열 방지
* `@Size`: 문자열 길이 제한
* `@Email`: 이메일 형식 확인
* `@Pattern`: 정규식을 이용한 전화번호 형식 확인

```java
@Pattern(
        regexp = "^01[016789]-?\\d{3,4}-?\\d{4}$",
        message = "전화번호 형식이 올바르지 않습니다."
)
String phoneNumber
```

정규식은 문자열 형식을 검사하기 위한 규칙이며, 현재는 전화번호 형식을 검증하는 용도로 적용했다.

### 5. AuthService 회원가입 로직 작성

`AuthService`에 회원가입 서비스 로직을 작성했다.

회원가입 처리 순서:

1. 로그인 아이디 중복 확인
2. 중복된 아이디라면 예외 발생
3. 평문 비밀번호 BCrypt 암호화
4. `SignupRequest`를 이용해 `User` 엔티티 생성
5. `UserRepository.save()`로 사용자 저장
6. 저장된 사용자의 ID 반환

```java
@Transactional
public Long signup(SignupRequest request) {

    if (userRepository.existsByLoginId(request.loginId())) {
        throw new IllegalArgumentException(
                "이미 존재하는 사용자입니다."
        );
    }

    String encodedPassword =
            passwordEncoder.encode(request.password());

    User newUser = new User(
            request.name(),
            request.loginId(),
            encodedPassword,
            request.phoneNumber(),
            request.email()
    );

    User savedUser = userRepository.save(newUser);

    return savedUser.getId();
}
```

학습한 내용:

* `throw`는 반환값이 아니므로 `return throw`로 작성할 수 없다.
* `IllegalArgumentException`은 `RuntimeException` 계열이라 메서드에 `throws`를 명시하지 않아도 된다.
* `save()`는 저장된 엔티티를 반환하므로 저장 후 다시 조회할 필요가 없다.
* 서비스 계층에서는 Spring의 `@Transactional`을 사용하는 것이 일반적이다.
* 예외가 발생하면 트랜잭션이 롤백된다.

## 발생한 문제

`@RequiredArgsConstructor`를 사용했지만 Eclipse에서 다음 오류가 발생했다.

```text
The blank final field passwordEncoder may not have been initialized
```

현재 `build.gradle`에는 Lombok 설정이 정상적으로 들어 있고 다른 프로젝트에서도 Lombok이 동작한다.

```gradle
compileOnly 'org.projectlombok:lombok'
annotationProcessor 'org.projectlombok:lombok'

testCompileOnly 'org.projectlombok:lombok'
testAnnotationProcessor 'org.projectlombok:lombok'
```

현재 프로젝트의 Eclipse Gradle 동기화, 빌드 캐시 또는 프로젝트 인식 문제일 가능성이 있다.

추가로 `build.gradle`에는 다음 중복 의존성이 있어 정리가 필요하다.

* PostgreSQL 드라이버 중복
* JUnit Platform Launcher 중복
