# 2026-07-27 SAI 백엔드 개발 기록

## 오늘 진행한 내용

### 1. Spring Boot 프로젝트 구조 정리

SAI 백엔드 프로젝트의 기본 패키지를 다음과 같이 설정했다.

```text
com.sai.backend
```

`src/main/java` 아래에서 기능별로 패키지를 나누는 구조를 사용하기로 했다.

```text
com.sai.backend
├── user
│   ├── domain
│   ├── repository
│   ├── service
│   ├── controller
│   └── dto
├── space
├── invitation
└── global
```

현재는 `user.domain` 패키지를 만들고 `User` 엔티티 구현부터 시작했다.

기능별 패키지 구조를 사용하면 사용자, 공간, 초대처럼 하나의 기능과 관련된 코드를 가까운 위치에 모을 수 있다.

### 2. PostgreSQL 연동

Spring Boot 프로젝트와 PostgreSQL 데이터베이스 연동을 완료했다.

현재 개발 환경은 다음과 같다.

* Spring Boot 4.1
* Java 21
* Gradle
* PostgreSQL
* Spring Data JPA
* Flyway

애플리케이션이 PostgreSQL에 정상적으로 연결되고, Flyway 마이그레이션을 실행할 수 있는 상태까지 구성했다.

### 3. Flyway 초기 스키마 작성

Flyway의 `V1` 마이그레이션에서 다음 테이블을 생성했다.

* `users`
* `space`
* `space_member`
* `space_invitation`

#### users

회원 정보를 저장하는 테이블이다.

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    login_id VARCHAR(50) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP NOT NULL,
    phone_number VARCHAR(20),
    email VARCHAR(255)
);
```

#### space

사용자가 참여할 공간을 저장한다.

```sql
CREATE TABLE space (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    created_at TIMESTAMP NOT NULL
);
```

#### space_member

사용자와 공간의 다대다 관계를 연결하는 중간 테이블이다.

```sql
CREATE TABLE space_member (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    space_id BIGINT NOT NULL,
    joined_at TIMESTAMP NOT NULL,

    CONSTRAINT fk_space_member_user
        FOREIGN KEY (user_id)
        REFERENCES users(id),

    CONSTRAINT fk_space_member_space
        FOREIGN KEY (space_id)
        REFERENCES space(id),

    CONSTRAINT uq_space_member_user_space
        UNIQUE (user_id, space_id)
);
```

한 사용자가 같은 공간에 중복 가입하지 못하도록 `(user_id, space_id)`에 UNIQUE 제약조건을 설정했다.

#### space_invitation

공간 초대 정보를 저장한다.

```sql
CREATE TABLE space_invitation (
    id BIGSERIAL PRIMARY KEY,
    space_id BIGINT NOT NULL,
    inviter_id BIGINT NOT NULL,
    invitee_id BIGINT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    created_at TIMESTAMP NOT NULL,

    CONSTRAINT fk_space_invitation_space
        FOREIGN KEY (space_id)
        REFERENCES space(id),

    CONSTRAINT fk_space_invitation_inviter
        FOREIGN KEY (inviter_id)
        REFERENCES users(id),

    CONSTRAINT fk_space_invitation_invitee
        FOREIGN KEY (invitee_id)
        REFERENCES users(id)
);
```

초대 상태의 기본값은 `PENDING`으로 설정했다.

### 4. User 엔티티 구현

`user.domain` 패키지에 `User` 엔티티를 작성했다.

```text
src/main/java/com/sai/backend/user/domain/User.java
```

#### 테이블 연결

```java
@Entity
@Table(name = "users")
public class User {
}
```

* `@Entity`: JPA가 관리하는 엔티티로 지정
* `@Table(name = "users")`: PostgreSQL의 `users` 테이블과 연결

#### 필드 정의

```java
private Long id;
private String name;
private String loginId;
private String passwordHash;
private LocalDateTime createdAt;
private String phoneNumber;
private String email;
```

Java에서는 camelCase를 사용하고, DB에서는 snake_case를 사용했다.

```text
loginId      → login_id
passwordHash → password_hash
createdAt    → created_at
phoneNumber  → phone_number
```

#### 기본키 매핑

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

* `@Id`: 기본키 필드 지정
* `@GeneratedValue`: 기본키 자동 생성
* `IDENTITY`: INSERT 시 PostgreSQL이 ID 생성
* `Long`: 저장 전 ID가 없는 상태를 `null`로 표현

Flyway의 다음 컬럼과 대응한다.

```sql
id BIGSERIAL PRIMARY KEY
```

#### 컬럼 매핑

```java
@Column(
        name = "name",
        nullable = false,
        length = 50
)
private String name;

@Column(
        name = "login_id",
        nullable = false,
        unique = true,
        length = 50
)
private String loginId;

@Column(
        name = "password_hash",
        nullable = false,
        length = 255
)
private String passwordHash;

@Column(
        name = "created_at",
        nullable = false,
        updatable = false
)
private LocalDateTime createdAt;

@Column(name = "phone_number", length = 20)
private String phoneNumber;

@Column(name = "email", length = 255)
private String email;
```

`name`은 표시 이름이므로 중복을 허용한다. 로그인에 사용하는 `loginId`만 UNIQUE로 설정한다.

실제 DB 스키마의 기준은 Flyway SQL이며, 엔티티의 `@Column` 설정은 DB 구조를 Java 코드에도 표현하기 위해 사용한다.

#### JPA 기본 생성자

```java
protected User() {
}
```

JPA가 조회한 데이터로 엔티티를 생성할 수 있도록 매개변수가 없는 생성자를 작성했다.

외부에서 의미 없이 기본 생성자를 호출하지 못하도록 `protected`로 제한했다.

#### 회원가입용 생성자

```java
public User(
        String name,
        String loginId,
        String passwordHash,
        String phoneNumber,
        String email
) {
    this.name = name;
    this.loginId = loginId;
    this.passwordHash = passwordHash;
    this.phoneNumber = phoneNumber;
    this.email = email;
}
```

ID는 PostgreSQL이 만들고, 생성 시간은 저장 시 자동으로 입력되므로 생성자에서 받지 않는다.

#### 생성 시간 자동 설정

```java
@PrePersist
private void prePersist() {
    if (this.createdAt == null) {
        this.createdAt = LocalDateTime.now();
    }
}
```

`@PrePersist`를 사용해 엔티티가 처음 저장되기 직전에 `createdAt`을 설정한다.

Flyway의 `created_at` 컬럼은 `NOT NULL`이면서 DB 기본값이 없으므로 저장 전에 애플리케이션에서 값을 넣어야 한다.

#### setter 제거

필드가 외부에서 무분별하게 변경되지 않도록 setter를 만들지 않고 getter만 작성했다.

추후 정보 변경 기능이 필요하면 단순 setter보다 의도가 드러나는 메서드를 작성한다.

```java
changeName(...)
changePassword(...)
changeContact(...)
```

## 오늘 이해한 내용

* 기본 패키지는 `com.sai.backend`처럼 점으로 구분한다.
* 실제 폴더는 패키지 구조에 따라 계층적으로 생성된다.
* 기능별 패키지 구조에서는 하나의 기능과 관련된 코드를 같은 영역에 모은다.
* Flyway는 DB 스키마의 변경 이력을 SQL 파일로 관리한다.
* 실제 DB 스키마의 기준은 Flyway 마이그레이션이다.
* JPA 엔티티는 DB 테이블을 Java 객체로 매핑한다.
* Java 필드명과 DB 컬럼명은 달라도 `@Column`으로 연결할 수 있다.
* JPA 엔티티에는 기본 생성자가 필요하다.
* DB가 자동 생성하는 ID는 생성자에서 받지 않는다.
* 엔티티 ID에는 저장 전 상태를 표현할 수 있는 `Long`이 적합하다.
* JPA는 setter 없이도 필드에 접근할 수 있다.
* `@PrePersist`로 최초 저장 직전 로직을 실행할 수 있다.
