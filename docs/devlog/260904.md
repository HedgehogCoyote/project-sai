# 2026-09-04 SAI 개발 기록

## 초대 요청 검증 보완

- `SpaceInvitationRequest`의 `spaceId`, `inviteeUserId`에 `@NotNull` 검증을 추가해 필수 값이 누락된 요청을 컨트롤러 계층에서 거절하도록 했다.
- 자기 자신 초대 여부를 엔티티 ID가 아닌 요청의 `inviterUserId`와 `inviteeUserId`로 비교하도록 변경했다.
- 자기 자신 초대 검사를 저장소 조회보다 먼저 수행하도록 옮겼다. 불필요한 DB 조회를 피하고, 아직 ID가 부여되지 않은 테스트 엔티티로 인해 `NullPointerException`이 발생하던 문제도 제거했다.
- `SpaceInvitationServiceTest`에서 자기 자신 초대 시 `SelfInvitationException`이 발생하는지 검증했다.

## 컨트롤러 테스트 보완

- `SpaceInvitationControllerTest`에 초대 ID 누락, 비로그인 요청, 보낸·받은 초대 목록 조회, 초대 수락·거절, 존재하지 않는 초대 수락 테스트를 추가했다.
- 보낸 목록은 `getSentInvitationList`, 받은 목록은 `getReceivedInvitationList`를 호출하도록 테스트 스텁과 요청을 일치시켰다.
- 수락과 거절 요청을 실제 엔드포인트인 `POST /api/invitations/join`, `POST /api/invitations/deny`에 맞췄다.
- 요청 본문을 유효한 JSON으로 수정해 역직렬화 오류가 인증 검사보다 먼저 발생하지 않도록 했다.
- `SpaceControllerTest`의 생성 URL에서 불필요한 후행 슬래시를 제거했다.
- 참여 스페이스 응답 검증 필드를 실제 DTO 필드명인 `spaceMemberCount`로 수정했다.

## 테스트 과정에서 확인한 점

- MockMvc의 `isUnauthorized()`는 401 응답을 생성하는 것이 아니라 실제 응답 상태를 검증한다. 잘못된 URL이면 컨트롤러에 도달하지 않아 404가 발생하고, 잘못된 JSON이면 인증 검사 전에 400이 발생한다.
- JPA 엔티티를 생성자로만 만든 단위 테스트 객체에는 ID가 자동으로 부여되지 않는다. 입력값만으로 판단할 수 있는 검증은 엔티티 조회 결과보다 요청 ID를 직접 비교하는 편이 안전하다.
- 컨트롤러 테스트의 서비스 스텁은 실제 엔드포인트가 호출하는 메서드와 사용자 ID까지 정확히 일치해야 한다.
