# 2026-09-01 SAI 개발 기록

## 직접 진행한 작업

- 초대 응답 DTO `InvitationResponse`와 엔티티를 변환하는 정적 팩토리 메서드 `from`을 작성했다.
- 초대 수락과 거절 요청 DTO인 `JoinSpaceRequest`, `DenySpaceRequest`를 작성했다.
- 초대 관련 예외 `SpaceInvitationNotFoundException`, `InvitationPermissionDenied`, `InvalidInvitationStatusException`, `SpaceInvitationAlreadyExistException`을 추가했다.
- `SpaceInvitation`에 상태를 변경하는 `accept`와 `denied` 메서드를 추가했다.
- `SpaceInvitation`의 `@JoinColumn` 이름이 V1 마이그레이션의 실제 컬럼명과 달라 `inviter_id`, `invitee_id`로 맞췄다.
- `SpaceInvitationRepository`에 보낸 초대와 받은 초대 조회 메서드, 그리고 중복 초대를 확인하는 `existsBySpace_IdAndInviter_IdAndInvitee_IdAndStatus`를 추가했다.
- `GlobalExceptionHandler`에 초대 관련 예외 처리기를 추가하고 상태 코드를 404, 409, 403으로 구분했다.
- `joinSpace`를 `SpaceService`에서 `SpaceInvitationService`로 옮겨 초대 관련 로직을 한 곳에 모았다.
- 초대를 거절하는 `denySpaceInvitation`을 구현했다.
- 초대 생성, 수락, 거절, 받은 목록, 보낸 목록까지 API 다섯 개를 `SpaceInvitationController`에 작성했다.
- Flyway V3 마이그레이션 파일에 `.sql` 확장자가 없어 적용되지 않던 문제를 수정했다.
- `Long` 값을 `!=`로 비교하던 부분을 `Objects.equals`로 바꿨다.

## AI에게 요청한 작업

- 프로젝트 전반의 코드 검토를 요청해 컬럼명 불일치, 보낸 초대와 받은 초대가 같은 쿼리를 쓰던 문제, `Long` 참조 비교 문제를 확인했다.
- 중복 초대를 어떤 기준으로 막을지 논의했다. 여러 사람이 같은 사용자를 초대할 수 있어야 하므로 초대자 기준으로 두고, 거절 이후 재초대는 가능하도록 `PENDING` 상태를 조건에 넣기로 했다.
- 거절 처리에서 Space 존재 검증이 필요한지 질문했고, 거절은 초대 상태만 바꾸므로 Space를 조회할 필요가 없다는 점을 확인했다.
- 저장소를 공개로 전환해도 되는지 점검을 요청했다. 자격 증명 유출은 없으나 테스트 코드와 개발 기록에 실제 전화번호와 이메일이 남아 있는 것을 확인했다.
- 컴파일과 테스트 실행 결과를 확인했다.

## 확인한 결과

- `compileJava`는 통과했다.
- 테스트는 26개 중 9개가 실패했다.
- 이 중 3개는 `DB_PASSWORD`가 설정되지 않은 환경에서 실행해 Spring 컨텍스트가 뜨지 못한 것으로, 코드 문제는 아니다.
- 나머지 6개는 8월 30일에 확인한 실패가 그대로 남아 있는 것이다.
- `SpaceServiceTest`의 `NullPointerException` 원인을 찾았다. `@MockitoBean`은 Spring 테스트 컨텍스트에서만 동작하는 애노테이션이라, `MockitoExtension`으로 도는 순수 단위 테스트에서는 무시되어 필드가 주입되지 않는다.
