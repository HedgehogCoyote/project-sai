## 완료한 작업

### 1. STS Lombok 인식 문제 해결

`@RequiredArgsConstructor`를 사용한 클래스에서 다음 오류가 발생했다.

```text
The blank final field passwordEncoder may not have been initialized
```

Gradle의 annotation processor 설정은 정상적으로 적용되고 있었다.

```text
org.projectlombok:lombok:1.18.46
BUILD SUCCESSFUL
```

현재 사용 중인 STS에 Lombok을 설치한 뒤 `Project > Clean`을 실행하여 해결했다.

원인은 Gradle 의존성 문제가 아니라 STS가 Lombok이 생성하는 생성자를 인식하지 못했던 것이었다.

### 2. 회원가입 API 구현 완료

회원가입 요청 흐름을 구현했다.

```text
외부 JSON 요청
→ SignupRequest DTO
→ AuthController
→ AuthService
→ User 엔티티 생성
→ UserRepository
→ PostgreSQL 저장
```

구현 내용:

- `SignupRequest`를 통한 요청 데이터 수신
- `@Valid`를 통한 입력값 검증
- 로그인 아이디 중복 확인
- BCrypt를 이용한 비밀번호 암호화
- `User` 엔티티 생성
- JPA Repository를 통한 사용자 저장
- 가입 성공 시 `201 Created` 응답

Postman 요청은 Query Params가 아니라 Body의 JSON으로 전달해야 한다는 점을 확인했다.

```json
{
  "name": "강태호",
  "loginId": "testuser",
  "password": "Test1234!",
  "email": "test@example.com",
  "phoneNumber": "010-1234-5678"
}
```

### 3. 중복 로그인 아이디 예외 처리

중복 사용자가 존재할 때 기존에는 처리되지 않은 예외로 인해 `500 Internal Server Error`가 반환됐다.

이를 다음 구조로 개선했다.

```text
DuplicateLoginIdException 발생
→ GlobalExceptionHandler 처리
→ 409 Conflict 응답
```

오류 응답 DTO:

```json
{
  "code": "DUPLICATE_LOGIN_ID",
  "message": "이미 존재하는 사용자입니다."
}
```

구현한 구성:

- `DuplicateLoginIdException`
- `ApiErrorResponse`
- `GlobalExceptionHandler`
- `@RestControllerAdvice`
- `@ExceptionHandler`

### 4. 로그인 API 구현

로그인 요청 DTO를 작성하고 로그인 로직을 구현했다.

```text
외부 JSON 요청
→ LoginRequest
→ AuthController
→ AuthService
→ loginId로 사용자 조회
→ BCrypt 비밀번호 비교
→ 세션에 사용자 ID 저장
→ 로그인 응답
```

로그인 요청:

```json
{
  "loginId": "testuser",
  "password": "Test1234!"
}
```

Service에서 수행한 작업:

- `findByLoginId()`로 사용자 조회
- 사용자가 없으면 `InvalidLoginException` 발생
- `passwordEncoder.matches()`로 비밀번호 검증
- 로그인 성공 시 사용자 PK 반환

로그인에서는 비밀번호를 다시 `encode()`한 뒤 비교하지 않고 다음 방식으로 확인했다.

```java
passwordEncoder.matches(
    loginRequest.password(),
    foundUser.getPasswordHash()
);
```

### 5. 세션 기반 로그인 처리

로그인 성공 후 Controller에서 사용자 ID를 세션에 저장했다.

```java
session.setAttribute("LOGIN_USER_ID", userId);
```

세션에는 사용자 객체 전체나 비밀번호가 아니라 사용자 ID만 저장했다.

Postman에서 `localhost` 도메인의 `JSESSIONID` 쿠키가 생성된 것을 확인했다.

```text
JSESSIONID
```

로그인 성공 응답:

```json
{
  "userId": 2
}
```

### 6. 로그인 실패 예외 처리

아이디가 없거나 비밀번호가 일치하지 않는 경우 동일한 예외 응답을 반환하도록 구현했다.

```json
{
  "code": "INVALID_LOGIN",
  "message": "아이디나 비밀번호가 다릅니다."
}
```

아이디 존재 여부를 외부에 노출하지 않도록 아이디 오류와 비밀번호 오류를 같은 메시지로 처리했다.

## 오늘 이해한 내용

### DTO, Service, Domain, Repository의 흐름

```text
외부 요청
→ Request DTO로 요청 형식 정의
→ Controller가 요청 수신
→ Service가 비즈니스 로직 수행
→ Domain 또는 Entity 생성 및 사용
→ Repository를 통해 DB 접근
```

응답은 반대 방향으로 전달된다.

```text
DB
→ Repository
→ Service
→ Response DTO
→ Controller
→ 외부 응답
```

### `@RequestBody`

HTTP Body의 JSON을 Java DTO로 변환한다.

```java
@Valid @RequestBody LoginRequest request
```

### `@Valid`

DTO에 선언한 `@NotBlank`, `@Size`, `@Email` 등의 검증 조건을 실행한다.

### `@RequiredArgsConstructor`

기본 생성자가 아니라 `final` 필드를 매개변수로 받는 생성자를 Lombok이 생성한다.

### `@RestControllerAdvice`

여러 Controller에서 발생한 예외를 한곳에서 공통으로 처리한다.

### `ResponseEntity.status().body()`

직접 `new ResponseEntity(...)`를 호출하지 않아도 Builder 메서드 내부에서 최종 응답 객체를 생성한다.
